# Oracle Machine Learning локально, без Oracle Cloud

Методичні блокноти курсу (`OML4SQL ...`) написані під Oracle Autonomous Database
і припускають, що студент має обліковий запис в Oracle Cloud. Реєстрація в OCI
вимагає платіжної картки і регулярно не проходить.

Обхід: **Oracle Database Free** у контейнері podman на власній машині.
Безкоштовна редакція містить пакет `DBMS_DATA_MINING` і опцію Oracle Machine
Learning, тому всі лабораторні з Data Miner, OML4SQL Time Series, Association
Rules і класифікації виконуються без хмари. Відрізняється лише спосіб
підключення: не вебінтерфейс OML Notebooks, а `sqlplus` усередині контейнера.

## Що потрібно

| Ресурс | Мінімум | Примітка |
|---|---|---|
| ОС | Ubuntu, зокрема у WSL2 | перевірено на WSL2 під Windows 11 |
| podman | 4.x і новіші | перевірено на 5.7.0 |
| Вільний диск | 15 ГБ | образ займає ~6 ГБ на диску, качається ~10 ГБ |
| Вільна памʼять | 3 ГБ | сам Oracle займає ~2,5 ГБ |
| Час запуску | ~1 хв | база вже створена всередині образу |
| Час завантаження образу | 10–60 хв | залежить від каналу, робиться один раз |

Якщо podman немає: `sudo apt-get update && sudo apt-get install -y podman`

## Запуск

```bash
chmod +x setup.sh smoke_test.sh
./setup.sh
```

Скрипт ідемпотентний — його можна запускати повторно. Він перевіряє
передумови, генерує паролі, тягне образ, піднімає контейнер, **дочікується
готовності реальним SQL-запитом**, створює навчальну схему й перевіряє,
що `DBMS_DATA_MINING` на місці.

Якщо образ уже завантажено, від запуску до готової схеми минає близько
хвилини — на відміну від старих образів XE, тут база вже створена всередині
образу і не збирається при першому старті. Заміряно: 42 секунди.

Перевірити, що працює весь ланцюжок до побудови моделі:

```bash
./smoke_test.sh
```

Скрипт створює тестовий ряд на 36 місяців, будує модель `EXSM_WINTERS`
і виводить прогноз на 3 місяці. Якщо він пройшов — середовище придатне
для лабораторних.

## Завантаження датасету

Методички пропонують заливати CSV через APEX. У Free-контейнері APEX немає,
тому використовується скрипт, який створює таблицю й наповнює її
згенерованими INSERT-ами:

```bash
python3 load_csv.py pdfo02.csv PDFO02
```

Типи стовпців визначаються автоматично (`NUMBER`, `DATE`, `VARCHAR2`),
дати розпізнаються у форматах `MM/DD/YYYY`, `DD.MM.YYYY`, `YYYY-MM-DD`,
`DD/MM/YYYY`. Для інших роздільників і кодувань:

```bash
python3 load_csv.py data.csv MYTAB --delimiter ';' --encoding cp1251
python3 load_csv.py data.csv MYTAB --dry-run   # лише показати SQL
```

Підхід розрахований на навчальні обсяги — сотні й тисячі рядків.

## Підключення

```bash
podman exec -it oradb sqlplus omluser/"$(cat ~/.oml-local/omluser)"@FREEPDB1
```

Виконати готовий файл:

```bash
podman cp my.sql oradb:/tmp/
podman exec -i oradb bash -lc 'sqlplus -s omluser/"PWD"@FREEPDB1 @/tmp/my.sql'
```

## Налаштування

Поведінка керується змінними оточення:

| Змінна | Типово | Що робить |
|---|---|---|
| `ORA_CONTAINER` | `oradb` | назва контейнера |
| `ORA_PORT` | `1521` | порт на хості |
| `ORA_LAB_USER` | `omluser` | навчальна схема |
| `ORA_SECRETS_DIR` | `~/.oml-local` | де лежать паролі |
| `ORA_WAIT_MIN` | `20` | скільки хвилин чекати готовності |

Паролі генеруються випадково і зберігаються у файлах із правами `600`.
У скриптах вони не захардкоджені.

## Граблі

**Памʼяті не вистачає на Hadoop і Oracle одночасно.** На машині з 8–9 ГБ
доведеться вибирати. Перед запуском бази зупиніть кластер:

```bash
source ~/.hadoop_env && stop-yarn.sh && stop-dfs.sh
```

`setup.sh` це перевіряє і зупиняється сам, якщо бачить запущений NameNode.

**`podman ps` показує `(starting)`, хоча база вже працює.** Вбудована
healthcheck-перевірка образу може висіти в цьому стані годинами. Орієнтуватись
треба не на статус і не на рядок `DATABASE IS READY TO USE` у логах — лог
лишається від попередніх запусків і дає хибний сигнал. Єдина надійна перевірка —
виконати запит. Саме так робить `setup.sh`.

**`podman ps` показує `Exited (0) 292 years ago`.** Наслідок зсуву годинника
у WSL після сплячки. На роботу не впливає.

**`$` ламається в укладених лапках.** Конструкція виду
`podman exec -i oradb bash -c "sqlplus ... <<EOF ... v\$version ... EOF"`
мовчки підставляє порожній рядок замість `$version`. Пишіть SQL у файл
і передавайте через `podman cp`, а не вкладеними heredoc-ами.

**`ORA-01017: invalid username/password`.** Пароль `SYSTEM` задається один раз
при створенні контейнера. Якщо файл із паролем загублено, змінити його ззовні
не можна — тільки перестворити базу:

```bash
./setup.sh --recreate     # видаляє контейнер разом з усіма даними
```

**Модель не будується, `ORA-01031: insufficient privileges`.** Схемі бракує
права `CREATE MINING MODEL`. `setup.sh` його видає; якщо схему створювали
вручну — додайте.
